# BattleBlaster 产品需求文档

> 版本: v1.1
> 状态: 以当前代码实现为准，兼顾后续规划
> 最后更新: 2026-05-15
> 相关文档: `Docs/02-developer-guide.md`, `Docs/03-api-reference.md`

## 1. 产品定位

BattleBlaster 是一款本地分屏坦克动作游戏，核心体验是 1-4 名玩家在同一台设备上进行快节奏炮战。游戏目前围绕坦克操控、炮弹碰撞、Buff、可破坏场景、AI 敌人和多模式规则展开。

当前项目不是联网游戏，现有多人能力以本地多人、本地分屏、手柄/键盘输入映射为主。未来如果要扩展在线联机，需要单独设计复制、同步、预测和服务器权威规则。

## 2. 当前实现范围

### 2.1 已实现模式

| 模式 | 当前状态 | 核心目标 |
| --- | --- | --- |
| Free For All | 已实现 | 2-4 名玩家/AI 混战，达到目标分数获胜 |
| Team Battle | 已实现 | 4 个槽位固定组队，红蓝两队积分对抗 |
| MOBA | 已实现 | 每名玩家一个阵营，通过防御塔、核心塔和淘汰机制决胜 |
| Stage | 已实现 | 单人 PVE 关卡，摧毁全部 Tower 获胜 |
| Defense | 占位 | 菜单入口存在，但玩法代码尚未实现 |
| Test | 已实现/开发用 | 用于调试地图和基础系统验证 |

### 2.2 暂未实现或非目标

- Defense 模式目前没有完整玩法规则和运行时代码。
- 当前项目没有在线联机、大厅匹配、网络同步和远程客户端支持。
- 当前 Source 目录仍是扁平结构，功能模块分类是后续迁移目标，不是当前工程事实。

## 3. 目标玩家与体验

### 3.1 目标玩家

- 喜欢本地多人对战的玩家。
- 需要快速开局、低学习成本、强反馈炮战体验的玩家。
- 喜欢可破坏场景、Buff 反转和局内混战的玩家。

### 3.2 体验关键词

- 即时反馈: 开火、命中、爆炸、受击和死亡都应有清晰反馈。
- 本地同屏: 多玩家应能在分屏中清楚看到自己的 HUD、准星、血条和局势。
- 规则直观: 模式目标、得分、复活、淘汰状态要能从 UI 和实际行为中快速理解。
- Buff 反转: Buff 应改变局部战术，但不应破坏核心命中规则。

## 4. 核心玩法系统

### 4.1 坦克

坦克是玩家和 AI 的主要可控单位，继承自 `ABasePawn`，并在 `ATank` 中扩展输入、摄像机、HUD、弹药、Buff、死亡流程和奖励逻辑。

主要能力:

- 移动、转向、炮塔瞄准。
- 普通开火、双发、强化伤害、穿墙弹等 Buff 加成。
- 弹药消耗、弹药恢复和 HUD 同步。
- 死亡、复活、短暂无敌、击杀奖励。
- 本地分屏下的独立玩家索引、独立 HUD 和独立输入。

### 4.2 炮弹

炮弹是核心战斗判定对象。当前实现中，普通玩家炮弹和 MOBA 防御塔炮弹分为:

- `AProjectile`: 玩家、Tower 和普通战斗用炮弹。
- `ATurretProjectile`: MOBA Turret 使用的追踪炮弹。

关键规则:

- 炮弹使用专用 `Projectile` 碰撞通道。
- 炮弹与坦克、Tower、Turret、可破坏对象保持命中关系。
- 炮弹与炮弹相撞会抵消，这是设计特色，应保留。
- Pierce Buff 当前语义是“穿墙弹”，即忽略世界静态/动态障碍，但仍应命中 Pawn 和可破坏物。
- Ghost Buff 不能让玩家免疫炮弹。Ghost 只改变与世界几何的碰撞关系，Projectile 通道必须保持 Block。

### 4.3 生命值与死亡

生命系统由 `UHealthComponent` 统一承担。

核心规则:

- 伤害先消耗护盾，再消耗生命。
- 生命变化通过委托通知 UI 和玩法逻辑。
- 生命降至 0 时触发死亡委托。
- 各模式负责解释死亡后行为，例如复活、扣分、淘汰或游戏结束。

### 4.4 Buff

Buff 由 `UTankBuffComponent` 管理，拾取物由 `ABuffPickup` 提供。

当前 Buff:

| Buff | 设计意图 | 当前行为重点 |
| --- | --- | --- |
| Heal | 即时恢复 | 恢复生命 |
| Ammo | 无限火力窗口 | UI 显示 9999，真实弹药在结束后恢复 |
| Speed | 高机动 | 速度翻倍，结束前逐渐衰减 |
| Pierce | 穿墙弹 | 炮弹忽略世界障碍，仍命中角色和可破坏对象 |
| Ghost | 穿越地形 | 与世界几何改为 Overlap，但仍会被炮弹击中 |
| Damage | 强化火力 | 提升炮弹伤害 |
| DoubleShot | 双发 | 一次开火发射两枚炮弹 |
| Shield | 护盾 | 先抵消受到的伤害 |
| RandomIcon | 随机外观 | 拾取时映射为实际 Buff |

Stage 模式中 Buff 拾取物不会自动重生；其他模式默认会重生。

### 4.5 可破坏对象与场景机关

当前场景交互对象包括:

- `ADestructibleProp`: 可破坏对象基类，带生命值、血条和距离检测。
- `ATurret`: MOBA 防御塔，继承自可破坏对象。
- `AExplosiveBarrel`: 爆炸桶，死亡后产生范围伤害。
- `AWoodenCrate`: 木箱，死亡后播放破坏反馈并延迟销毁。
- `ASpikeTrap`: 地刺陷阱，按状态机伸出、造成伤害、收回。
- `ASlideTrack`: 滑行轨道，改变坦克速度并支持重叠轨道计数。
- `ATeleportPortal`: 传送门，传送 Actor、炮弹和物理对象。
- `ARisingGate`: 升降门，由触发区域控制升起和落下。

血条显示要求:

- 本地分屏下，任意玩家进入检测范围都应显示可破坏对象血条。
- 不应只检查 Player 0。

## 5. 游戏模式需求

### 5.1 Free For All

### 目标

每个玩家或 AI 均为独立阵营，击杀其他单位获得积分，达到目标分数后胜利。

### 规则

- 支持 2-4 个槽位。
- 本地玩家由 `UGameInstance` 中的玩家设置决定。
- 空槽位可由 AI 填充。
- 每个槽位使用对应 PlayerStart。
- 击杀其他玩家加分。
- 自杀或无有效击杀者时，受害者扣分。
- 达到目标分数后进入游戏结束状态。

### 复活

- 非游戏结束时，死亡玩家进入延迟复活。
- 复活时恢复部分生命和弹药。
- 已保存 Buff 会在复活后恢复。
- 复活后短暂无敌，避免刚出生立即死亡。

### 5.2 Team Battle

### 目标

红蓝两队对抗，团队分数达到目标分后获胜。

### 当前阵营分配

- Player 0 和 Player 2 属于 Red。
- Player 1 和 Player 3 属于 Blue。

### 规则

- 当前模式以 4 个槽位为核心设计。
- 友军伤害应被阻止。
- 击杀敌方为所属队伍加分。
- 自杀或无有效击杀者时扣对应队伍分。
- 分数达到目标后进入游戏结束状态。

### 5.3 MOBA

### 目标

每名玩家拥有一个阵营，通过摧毁防御塔、核心塔并淘汰其他阵营来获得胜利。

### 关键对象

- `ATurret`: MOBA 防御塔，继承自 `ADestructibleProp`。
- Core Turret: 核心塔，属于特殊 Turret。
- Outer Turret: 外围塔，用于保护同阵营核心塔。
- `ATurretProjectile`: Turret 发射的追踪炮弹。

### 防御塔规则

- Turret 会注册到 `ATankMOBAGameState`。
- Turret 只攻击敌方 `ATank`。
- Turret 不把 `ATower` 当作攻击目标。
- 同阵营玩家攻击自己的 Turret 会治疗它。
- 核心塔在同阵营外围塔仍存在时免疫伤害。
- Turret 被摧毁后会切换废墟表现，并通知 MOBA GameState 更新计数和 UI。

### 死亡、复活与淘汰

当前代码中的 MOBA 胜负不是“核心塔一被摧毁就立刻全队失败”。

实际规则:

- 玩家核心塔仍存在时，死亡后进入等待复活。
- 复活倒计时会随死亡次数增长。
- 玩家核心塔被摧毁后，该玩家再次死亡会进入淘汰状态。
- 被淘汰玩家不再复活。
- 游戏结束条件是: 只剩一个未淘汰阵营。
- 核心塔数量不直接决定胜负；核心塔只决定该阵营玩家死亡后是否还能复活。

### UI 需求

- 顶部状态 UI 需要显示各阵营核心塔/防御塔状态。
- 核心塔被摧毁后，应隐藏或更新对应核心塔图标。
- 死亡玩家应看到死亡倒计时。
- 淘汰玩家应看到淘汰状态。
- 游戏结束时显示胜利阵营。

### 5.4 Stage

### 目标

单人 PVE 关卡，玩家摧毁当前关卡内所有 `ATower` 后胜利。

### 关键对象

- `ATower`: 游戏中的 NPC 敌人，继承自 `ABasePawn`。
- `ATower` 当前主要服务 Stage/PVE 和 AI 目标系统，不是 Defense 模式专属建筑。

### 规则

- Stage 只生成 Player 0。
- 玩家从随机 PlayerStart 出生。
- Tower 会扫描场上的坦克并攻击。
- Tower 的难度会随 Stage 难度参数调整。
- Tower 在 Stage 模式中被摧毁后不会自动复活。
- Buff 拾取物在 Stage 模式中不会自动重生。
- 玩家生命数耗尽则失败。
- 摧毁所有 Tower 则胜利。

### 关卡衔接

- Stage 结束前会保存玩家生命、护盾、弹药和 Buff。
- 下一关开始时尝试恢复上一关携带状态。
- 关卡历史和结果由 GameInstance/SaveGame 体系记录。

### 5.5 Defense

### 当前状态

Defense 模式目前是规划项/占位项。

当前代码中:

- 存在 `ADefenseGameMode` 空类。
- Stage 开始菜单中存在 Defense 按钮入口。
- 点击入口后会保存坦克选择并打印“守卫模式暂未开放！”。
- 尚未实现 Defense 专用敌人波次、基地生命、资源、建造、防守胜负等规则。

### 后续可设计方向

Defense 后续可以独立设计为:

- 单人或多人合作防守。
- 波次刷怪。
- 基地或核心目标生命值。
- 资源、建造、升级和维修。
- 防御塔建造系统。

但在当前文档和代码分类中，不应把 `ATower` 误归为 Defense 代码。

## 6. AI 需求

### 6.1 AI Bot

`AAIBotPlayerController` 负责普通 AI 坦克行为。

当前行为重点:

- 扫描并维护攻击目标列表。
- 可攻击 `ATank`、`ATower`、`ATurret`。
- 根据难度调整行为参数。
- 在攻击、追逐、搜索、逃离等状态间切换。
- 被攻击时可响应攻击者。

### 6.2 Tower AI

`ATower` 自身实现目标扫描和开火逻辑。

当前行为重点:

- 使用检测球维护范围内目标。
- 选择最近存活坦克。
- 用可见性射线检测目标是否被阻挡。
- 目标可见时旋转炮塔并开火。
- 死亡后按模式决定是否复活。

### 6.3 Turret AI

`ATurret` 是 MOBA 防御塔。

当前行为重点:

- 周期性搜索视野内敌方坦克。
- 忽略同阵营坦克和非合法目标。
- 发射追踪型 `ATurretProjectile`。
- 核心塔免疫逻辑由外围塔存活状态决定。

## 7. UI 需求

### 7.1 主菜单与设置

主菜单需要支持:

- 进入模式选择。
- 配置玩家数量、AI 数量、目标分数和难度。
- 配置坦克选择。
- 配置游戏设置。
- 查看关卡历史。

相关 Widget:

- `UMainMenuWidget`
- `UGameSettingsMenuWidget`
- `UMutiPlayerMenuWidget`
- `UMutiBattleMenuWidget`
- `UTeamBattleMenuWidget`
- `UMOBASetupWidget`
- `USelectMapWidget`
- `UTankStageStartWidget`

### 7.2 局内 HUD

玩家 HUD 需要支持:

- 生命值与护盾。
- 弹药。
- Buff 列表和剩余时间。
- KDA/分数。
- Death Screen。
- Eliminated Screen。
- Pass Widget。
- MOBA 顶部状态。

本地分屏要求:

- 每个本地玩家拥有自己的 HUD。
- HUD 添加到对应 Player Screen。
- 不应让 Player 0 的 HUD 状态污染其他玩家。

### 7.3 结算 UI

结算 UI 需要按模式显示:

- Free For All 胜利玩家和排行。
- Team Battle 胜利队伍、队伍分数和玩家数据。
- MOBA 胜利阵营、核心塔状态和玩家表现。
- Stage 胜利/失败、关卡结果和历史记录。

## 8. 数据与保存

### 8.1 GameInstance

`UBattleBlasterGameInstance` 是跨地图数据中心。

需要保存:

- 玩家数量、AI 数量、目标分数。
- 每个玩家选择的坦克类。
- 每个玩家的颜色、设备映射和输入配置。
- Stage 当前关卡、难度、历史记录。
- MOBA 玩家数量和选择。
- 战斗结束结果。

### 8.2 SaveGame

当前存档类型:

| 类型 | 用途 |
| --- | --- |
| `UBattleBlasterSaveGame` | 保存单人战役进度，例如当前关卡和历史最高关卡 |
| `UBattleBlasterHistorySaveGame` | 保存多人死斗历史战绩池，默认保留前 50 条 |

要求:

- 进度存档和多人历史战绩应互相独立。
- 多人历史可按分数和顺序展示。
- 存档读写不应影响当前局内运行状态。

## 9. 碰撞与规则约束

### 9.1 必须保留的设计特色

- 炮弹与炮弹相撞抵消。
- Pierce Buff 只能绕过地形，不应绕过玩家命中。
- Ghost Buff 不能免疫炮弹。
- MOBA 同阵营攻击 Turret 是治疗，不是伤害。
- MOBA 核心塔受到外围塔保护时免疫伤害。

### 9.2 常见回归风险

- 只用 `GetFirstPlayerController()` 导致分屏玩家看不到 UI 或血条。
- Ghost 修改碰撞时误把 Projectile 也改为 Overlap。
- Pierce 修改炮弹碰撞时误忽略 Pawn。
- 把 `ATower` 和 `ATurret` 混为同一类防御建筑。
- 把 MOBA 核心塔摧毁误写成即时游戏结束。
- Stage 里误让 Tower/Buff 继续按多人模式重生。

## 10. 验收清单

### 10.1 通用战斗

- 玩家炮弹能击中普通坦克。
- 玩家炮弹能击中 Ghost 状态坦克。
- Pierce 炮弹能穿过墙体。
- Pierce 炮弹仍能击中玩家、AI、Tower、Turret 和可破坏物。
- 炮弹与炮弹相撞会抵消。
- Damage、DoubleShot、Ammo 等 Buff 在 UI 和实战中同步正确。

### 10.2 分屏

- Player 0-3 均能看到自己的 HUD。
- 任意玩家靠近可破坏对象都能触发血条显示。
- 玩家死亡、复活、淘汰 UI 不串屏。
- 暂停菜单和输入焦点符合当前设计。

### 10.3 Free For All

- 玩家/AI 正确生成。
- 击杀、扣分和目标分数正确。
- 游戏结束后不再继续复活。
- 复活后生命、弹药、Buff 和无敌状态正确。

### 10.4 Team Battle

- 红蓝阵营分配正确。
- 友军伤害被阻止。
- 团队分数正确。
- 胜利队伍和结算数据正确。

### 10.5 MOBA

- Turret 只攻击敌方坦克。
- 同阵营攻击 Turret 会治疗。
- 核心塔在外围塔存在时免疫。
- 核心塔被毁后，对应玩家不会立刻失败，但下一次死亡会被淘汰。
- 只剩一个未淘汰阵营时游戏结束。
- 顶部状态 UI、死亡 UI、淘汰 UI、游戏结束 UI 更新正确。

### 10.6 Stage

- 玩家随机出生。
- Tower 能正确锁定和攻击玩家。
- Tower 死亡计数正确。
- 摧毁所有 Tower 后胜利。
- 玩家生命数耗尽后失败。
- Stage 中 Tower 和 Buff 不自动重生。
- 关卡结束状态能正确写入历史。

## 11. 后续路线建议

### 11.1 短期

- 按功能模块整理 Source 目录。
- 补充碰撞规则自动化测试或调试地图。
- 统一模式结算 UI 的数据接口。
- 为 MOBA 规则补充更清楚的 UI 文案。

### 11.2 中期

- 完成 Defense 模式立项文档和原型实现。
- 增强 AI 行为树或状态机可视化调试。
- 优化本地多人设备映射和断连处理。
- 完善 Stage 关卡选择、历史统计和难度曲线。

### 11.3 长期

- 如果需要在线多人，重新设计网络架构。
- 将跨模式规则抽象为更稳定的数据驱动配置。
- 建立自动化回归测试地图，覆盖碰撞、Buff、复活和结算。
